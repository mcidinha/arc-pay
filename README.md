# ArcPay

Payments dApp on Arc Testnet that records every USDC payment as a numbered, auditable invoice directly on a smart contract - no database, no off-chain source of truth. Sign in with your wallet, pay in USDC, and get an onchain invoice plus an email receipt.

🔗 **Live app:** [arcpayapp.com](https://arcpayapp.com)
📄 **Contract:** [`0x96e1D2564CB904445eF05688671Ee05c76aedeE4`](https://testnet.arcscan.app/address/0x96e1D2564CB904445eF05688671Ee05c76aedeE4) (deployed and verified)

## What ArcPay does

- Sign in with a connected wallet (MetaMask or compatible)
- Send USDC with a service description
- Every payment generates a sequential invoice number (001/07/2026)
- The invoice is written onchain: number, description, amount, sender, recipient, timestamp
- An email receipt is sent with the link to the onchain transaction
- Anyone can read the full invoice history straight from the contract

## What makes it different

Most payment demos move tokens and log the result off-chain. ArcPay records the invoice **inside the contract, in the same transaction as the payment**. The invoice number is not generated by the app - it comes from the payment's sequential id onchain, so it cannot be faked, skipped or duplicated.

## How a payment works

| Step | What happens |
|---|---|
| 1 | User signs in with a connected wallet on Arc Testnet |
| 2 | Enters recipient address, amount and a service description |
| 3 | App runs `approve` (authorize the contract to move USDC) |
| 4 | App calls `pay` - transfers USDC and records the invoice in the same transaction |
| 5 | Both parties can verify the USDC transfer and the invoice on ArcScan |

## Smart contract

| Function | What it does |
|---|---|
| `pay(to, amount, description)` | Transfers USDC from payer to recipient and records the invoice |
| `paymentsCount()` | Returns how many invoices exist |
| `latestPayment()` | Returns the most recent invoice |
| `payments(id)` | Reads a specific invoice |

Emits a `PaymentMade` event (id, sender, recipient, amount, description, timestamp), which the app reads to build the invoice number. Deployed and verified on Arc Testnet, so the source code is readable on the explorer.

## Getting started (local)

```bash
# install dependencies
npm install

# run the dev server
npm run dev
```

Optional `.env` for the email endpoint:

```
EMAIL_SENDER=your_email@gmail.com
EMAIL_PASSWORD=your_gmail_app_password
```

The `.env` is never committed. Email credentials are set as environment variables in the hosting provider.
