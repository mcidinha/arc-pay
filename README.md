# ArcPay

**USDC payments on Arc Testnet with onchain invoicing - every payment is recorded on a smart contract as a numbered, auditable invoice.**

🔗 **Live app:** [arcpayapp.com](https://arcpayapp.com)

📄 **Contract (Arc Testnet):** [`0x96e1D2564CB904445eF05688671Ee05c76aedeE4`](https://testnet.arcscan.app/address/0x96e1D2564CB904445eF05688671Ee05c76aedeE4)

---

## What it does

ArcPay lets you send USDC and receive payments on Arc Testnet, where every payment becomes an invoice written directly into a smart contract. There is no database acting as the source of truth: the invoice lives on the blockchain, and anyone can verify it on the explorer.

- 🔐 Sign in with a connected wallet (MetaMask)
- 💸 Send USDC with a service description
- 🧾 Each payment generates a sequential invoice number (001/07/2026)
- ⛓️ The invoice is recorded onchain: number, description, amount, sender, recipient and timestamp
- 📧 An email receipt is sent with the link to the onchain transaction
- 🔎 Anyone can read the full invoice history straight from the contract

## What makes it different

Most payment demos just move tokens and log the result off-chain. ArcPay records the invoice **inside the contract, in the same transaction as the payment**.

The invoice number is not generated by the app - it comes from the payment's sequential id onchain. That means the number cannot be faked, skipped or duplicated: it is derived from the blockchain itself.

Each invoice permanently stores:

- Sequential number
- Service description
- Amount in USDC
- Sender and recipient addresses
- Timestamp

## How payment works

1. The user signs in with a connected wallet on Arc Testnet.
2. They enter the recipient address, amount and a service description.
3. The app runs an `approve` (authorize the contract to move USDC), followed by `pay`.
4. `pay` transfers the USDC from the payer to the recipient and records the invoice in the same transaction.
5. Both parties can open the transaction on ArcScan and see the ERC-20 USDC transfer and the recorded invoice.

Payments are signed by the connected wallet. On Arc, USDC is used both as the payment asset and to pay the gas.

## Smart contract

| Function | What it does |
|---|---|
| `pay(to, amount, description)` | Transfers USDC from payer to recipient and records the invoice |
| `paymentsCount()` | Returns how many invoices exist |
| `latestPayment()` | Returns the most recent invoice |
| `payments(id)` | Reads a specific invoice |

The contract emits a `PaymentMade` event (id, sender, recipient, amount, description, timestamp), which the app reads to build the invoice number.

## Tech stack

- **Frontend:** React + Vite
- **Blockchain library:** viem
- **Wallet & auth:** Dynamic
- **Smart contract:** Solidity, deployed on Arc Testnet
- **Email:** serverless endpoint (Nodemailer)
- **Hosting:** Vercel + custom domain

## Getting started (local)

```bash
# install dependencies
npm install

# run the dev server
npm run dev
```

Create a `.env` file for the email endpoint (optional):

```
EMAIL_SENDER=your_email@gmail.com
EMAIL_PASSWORD=your_gmail_app_password
```

The `.env` file is never committed. Email credentials are configured as environment variables in the hosting provider.
